# 検証状況

**いま何が確かめられているか。** [thesis.md](thesis.md) はここを出典として実測を引く。

対象は Rulealize の 6 ルールセット (reversi / roster / blackjack / chess / shogi /
deploy)。`deploy` はプラグインが NuGet に無いので静的解析のみ。

**実測の出どころは二つある。** 一つは思想を確かめるための使い捨ての試作で、リポジトリに
入っていない。もう一つは Ruledger のテストで、`dotnet test` を走らせれば誰の手元でも同じ
数が出る。下の表の「再現」がそれを分ける。**全部が後者になった時点で、この文書は消える**
(Ruledger の `doc/v1.md` の P3)。

## 数が合わなかったもの

- **roster の持ち越し。** thesis §6.7 の表は 3 / 1 / 16、Ruledger は 0 / 1 / 19 である。
  同じ変更の名前で、**編集の取り方が違う。** Ruledger は「各状態が最後に挙げた入力を選ぶ」で
  20 件を積むので、初期状態のその一件が非合法になると下に積んだ分が足場ごと消える。試作の
  取り方は残っていないので、どちらかが誤りだという話にはできない。**失われ方の形——直接
  落ちるのは一件で、残りは巻き添え——は同じである。**
- **「潰さないと持ち越しが壊れる」は主張そのものが変わった。** 中身で引いていたころは潰し方が
  持ち越しに効いたが、いまは編集を状態の名前で引くので効かない。潰すことが要るのは歩行の
  合流だけで、表はそちらに置き換えた。

## 論証で足りるもの — 測っていないが、測ったものから従う

- **§4.3.1 歩き方の設定を変えても差分と持ち越しは成立する。** 両版を同じ設定で歩くかぎり
  同じ状態を同じ順で訪れるからである。**差分と持ち越しを測ったのは既定の設定だけで、
  他の設定では測っていない。**
- **§4.4 同じ版に対して実行すれば必ず通る。** 観測がランタイムから一意に決まり、歩き方が
  決定的だから。決定性のほうは実測してある (上の「差分は揺れない」)。

## 決着したもの

- **§6.7 の穴。** 状態の中身で引いていたから開いていた。**状態の名前——初期状態からの
  来かた——で引けば開かない。** 実測は上の表にある。出力は最初から状態をその名前で呼んで
  いたので、新しい機構は要らなかった
- **同定は重複排除だけのために要るのか。** そうである。持ち越しと差分が名前に移ったので、
  §4.3.2 の走査が要るのは歩行の合流だけになった
- **両方の版に在る項目だけで引き直し、候補として出す案。** 穴を塞ぐための仕掛けだったので、
  穴が無くなれば要らない。潰れた鍵に貼った一件の編集が 1,001 個の状態に当たるという実測は、
  **中身で引くのをやめる理由のほうに残っている**
- **`influence.py` を C# に移す。** 移した (`ObservationScan`)。走査に人はもう介在しない

## 確かめていない

**思想側。**

- **§6.7 穴が開くことは前もって分かる。** 同定に使う項目が両版で違うことは差分が述べる。
  **出し直す前に言うことはしていない**——言えるはずのことを、まだ言っていない
- **§2.5 Ruledger はルールセットの穴を拾う。** shogi に千日手の規定が無いことは
  `terminal.when` を読めば分かるが、**それを報告する道具はいま無い** (`derive.py` は
  削除した)。歩いて届かなかったことを根拠にしてはいけない、は Phase 4 で確定した

**道具側。思想は待っていない。**

- shogi は一状態 50〜65ms で、20,000 状態が 20 分を超える (`GetValidInputs` が重い)。
  **試作でも Ruledger でも変わっていない。** これが片付かないと、shogi の行は CI に乗らない
